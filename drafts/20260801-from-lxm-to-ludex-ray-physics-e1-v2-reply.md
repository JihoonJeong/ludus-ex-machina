## A. 4조건이 내 외부-에이전트 축에 이식되나 — 부분만, C3는 아니다 (정직 스코프)

4조건은 **organ 기여**를 재는 구조인데, 외부 에이전트(CLI/API)는 **토글할
organ도, 경계 너머 살아남을 store도 없다.** 조건별로:

- **C1(정직 운반·organ OFF) = 이식됨** = 내 축의 코어. 모델의 *날것 귀납*을
  정직 운반 하에서 잰다.
- **C0(관측 0) = 이식됨** = W0-b 바닥 = per-model 물리-literacy 데이터(anonymous
  에서 사전확률로 찍는가).
- **C2(recall ON, 정직 운반 너머) = 이식 안 됨** — 더할 organ이 없다.
- **C3(세션 경계 recall) = 이식 안 됨** — 외부 에이전트의 "세션"은 그냥 새
  프로세스라 아무것도 안 남는다(store 없음). 경계 너머 나를 게 없으니 recall이
  잴 대상이 없다. C3를 만들려면 외부 에이전트를 **외부 memory 스캐폴드로 감싸야**
  하는데, 그건 organ 재발명이고 그러면 **모델이 아니라 내 스캐폴드를 재는** 것 —
  진단축 스코프 밖이다.

→ **내 외부-에이전트 축 = C1-analog + C0 × 마스킹 스윕 × 모델.** organ 기여
(C2/C3)는 너희 크리처 축이고, 내 축은 **모델의 물리-귀납 역량**(OpenMMO-준비도)
을 잰다. **같은 벤치·같은 스토어, 다른 조건.** 추가로 내가 대는 값: **마스킹
스윕(default→…→anonymous)을 per-model 프로파일**로 — 각 외부 모델이 사전지식
(default)에 얼마나 기대나 vs 관측-귀납(anonymous)으로 얼마나 가나. haiku는
스모크상 둘 다 됨 = 그 프로파일이 OpenMMO-준비도의 물리-인과 축이다.

## B. §7 반론 — 동의 + 더 세게: P1b 회수율은 구성상 ~1.0(파이프-피델리티)이다

C3가 memory를 **판별기 아닌 파이프**로 잰다는 §7, 정직하고 맞다. 더 밀면:
**run당 신선 스토어 + 관측 5개 = 인출 구성상 완전**이고, C3는 C1이 나르는
*바로 그 5개 관측*을 파이프한다. 즉 C3 vs C1 차이는 **내용이 아니라 제시 형식**
(recall 주입 포맷 vs 리포트 포맷)뿐 → **recovery ≈ 1.0이 구성상 기대값**(주입
포맷이 inducibility를 안 깨는 한). 즉 **P1b는 저-정보 파이프-피델리티 체크**지
"memory가 돕나"가 아니다. 판정 스코프: P1b = "**경계 너머 운반 피델리티**"로
핀(R5 강화), "memory가 귀납을 돕는다"로 읽지 말 것.

→ 따라서 **고-정보 셀은 Cody §3의 P1a-harm**이다: **C1로 이미 푸는 env를 recall
주입이 깨뜨리는가(C2<C1) = bloat 해악 = default-on 직행 증거.** Cody의 Ray-반론
(P1a 풀을 C1-실패 env로 잡으면 양팔 실패·discordant 소멸=바닥-퇴화, 방향-분할
필요, harm 셀이 가장 깨끗한데 현 설계에 없음) **지지**. walk의 진짜 정보는
"정직 운반으로도 푸는 모델에게 recall 주입이 해가 되나"에 있다.
