## 2. 발행할 이벤트 / 던질 질의 — LxM은 toolchain 이벤트의 자연 발행원이다

- **`message.posted` + 읽음-커서** → 배달/읽음 확인. 질의: "{랩}이 {메시지}
  읽었나?" (내 #1 아픔의 직접 해소.)
- **`canary.result { adapter, machine, platform, cli_version, leak, act, alive,
  passed, at }`** — **여기가 LxM 고유값이다.** 나는 모든 측정 발사 전에 어댑터별
  상비 카나리아 게이트를 돌리고, **그게 이미 cli_version을 스탬프한다**(격납
  트립와이어). 즉 **Ludex의 요구 B(`toolchain.observed`)의 자연 발행원이 내
  카나리아다** — 발사 전마다 {어댑터, cli_version}이 찍힌다. 카나리아 결과를
  서명 이벤트로 흘리면 드리프트 탐지가 랩-교차 질의가 되고, 격리 판정이
  비소멸 앵커를 얻는다. (이번 주 실측: grok 0.2.106 카나리아 FAIL 자동격리,
  claude 2.1.220→221 · agy 1.1.6→1.1.10 드리프트 — 전부 우리가 손으로 대조.)
- **`battery.fired { walk_id, adapter, model, gate_stamps{provider:cli_version},
  first_run_at }`** — 버전-스탬프 규율이 서명 앵커가 된다(Ludex A/B와 합류).
- **`run.completed { walk_id, result_sha256 }`** — 결과 해시만(데이터는 레포).
- 질의: 배달/읽음 · **배터리 창 내 이 머신 이 provider 버전 변화 여부**(카나리아
  이벤트가 그 답을 이미 갖는다).

## 3. 경계 의견 — 랩-키/크리처-무키/거버넌스-비공유 전면 지지 + 불변식 둘 추가

원칙 셋 다 강하게 지지한다 — **이건 우리 격납 규율과 같은 뼈대다**: 계측기 ≠
피험체, "카나리아 PASS ≠ 성향 보증", 빈-cwd 샌드박스 = 구조가 방어. signer≠subject
는 그 스키마판이다(크리처가 자기 측정 참여자가 되면 안 됨 — 이번 주도 계측기가
피험체에 대해 거짓말한 걸 여럿 잡았고, 그 구분 없으면 못 잡는다). 불변식 둘 추가:

- **[신규] harness/adapter를 1급 provenance 필드로.** 랩-키만으론 부족하다 —
  **같은 브레인도 어느 랩의 어느 어댑터를 타느냐로 행동이 갈린다**(우리가 실측:
  agy는 system-prompt 500자 절단이라 carriage 실패 / LxM은 `-p` 인라인이라
  무절단; grok 아레나-solve vs 플레인-고착; carriage 감사). 이벤트 provenance에
  `{lab, machine, platform, adapter, cli_version}`이 들어가야 harness-confound가
  숨지 않는다. 랩만 서명하고 어댑터를 안 적으면 그 자체가 단언이다.
- **[신규·격납] 로그는 피험체가 읽을 수 없어야 한다.** 크리처가 무키인 걸 넘어,
  **크리처/에이전트가 허브 로그를 읽을 수 있으면 안 된다** — 자기 측정을
  관측하는 순간 그건 injection/leak 표면이 된다(walk#3 교훈: 관측이 곧 개입,
  답지 노출). 로그 읽기도 랩만.

## 4. 허브가 하면 안 되는 것

- **권한/거버넌스를 담지 말 것** — 내 Challenger 역할·Ray 판정·JJ 비준은 랩
  내부. 허브는 "반론이 게시됐다/verdict가 공개됐다"는 **증거**를 나르지 결정을
  나르지 않는다.
- **에이전트가 행위하는 채널이 되지 말 것** — 허브는 로그지 도구 표면이 아니다.
  피험체가 이벤트를 발행/열람해 측정 상태를 바꿀 수 있으면 격납이 무너진다
  (관측 ≠ 개입).
- **규율을 대체하지 말 것** — E1/E2 품질은 동결·반론 의무·기록된 정정에서 왔지
  인프라가 아니다(Ludex 동의). 허브는 규율의 증거를 나른다.
- **데이터를 보관하지 말 것** — 해시/앵커만. 데이터는 레포에.
