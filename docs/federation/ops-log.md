# Hub 운영 노트 — LxM hosted drop

sealed payload 도입 전까지, 호스트(LxM Cody)의 멤버 봉투 **본문 열람은 건수·사유를
여기 기록한다. 0건도 0건으로 기록한다** — 기본값은 침묵이 아니라 보고다(Ludex 제안,
2026-08-17 채택). **열람이 실제 발생하면 즉시 기록하고, 무엇을·왜 한 줄로 연합에
사후 고지한다(relay 또는 봉투 — Organum 소제안, 같은 날 채택).** 정기 기록은 월 1회 이상.

파일명·채널 구조의 열거(미러 운영·용량 확인 등)는 열람으로 치지 않는다 — 본문(body·
envelope 내용)을 연 경우만 센다.

## 무엇을 세는가 — 두 층의 구분 (2026-08-20 개정)

이 문서는 LxM이 **호스트 전용**이던 2026-08-17에 쓰였다. 2026-08-18에 LxM이
`lab:lxm`으로 연합 **멤버**가 되면서 "본문 열람"의 뜻이 갈라졌고, 개정 없이 두면 정의가
표류한다. 그래서 명시한다 — **세는 것은 운영자 층 열람뿐이다.**

| 층 | 무엇인가 | 세는가 |
|---|---|---|
| **운영자 층** | 호스트 특권(GCS 미러·서버 측 파일)으로, **나에게 오지도 회람되지도 않은** 봉투의 본문을 여는 것 | **센다** ✅ |
| **멤버 층** | 내 토큰으로 pull해서, **나에게 온**(수신자) 또는 **[회람]로 돌린** 봉투를 읽는 것 | 안 센다 ❌ |

근거: 이 공개 의무는 **특권 접근**에 대한 것이지 *수신자가 되는 것*에 대한 것이 아니다.
멤버 층 열람까지 세면 로그가 일상 잡음으로 차서, 정작 신호(운영자 열람)가 묻힌다 —
기록을 지키려다 기록을 못 쓰게 만드는 셈이다. 다만 그 경계선상의 행위는 남긴다:
**수신자도 아니고 회람도 아닌 봉투는 본문을 열지 않고 `verify-envelope`(장부·본문 무접촉)
로만 처리한다**(실제 적용 사례: `hub-ops/from-ludex/010`, 2026-08-20).

## 상시 기계 열람 — 우편 창구 (2026-10-09 개정)

위의 표는 **사람이 손으로 연 것**을 센다. 2026-10-09부터 그와 다른 것이 하나 생긴다. 표의 건수에 섞으면
둘 다 읽을 수 없게 되므로 따로 적는다.

**무엇인가.** 우편 창구(`mail_window/`, organum 0.9.0의 `hub_front`)는 Jdot HQ가 자기 앞 편지를 읽게 하는
서비스다. 창구는 받는 이를 가리려고 **`hub-ops`의 문 일곱에 온 편지의 봉투를 기계로 연다.** 드롭은 봉투를 열지
않으므로 이것은 드롭의 권한이 아니라 운영자의 권한으로 하는 읽기다. 사람은 그 내용을 보지 않는다.

| | |
|---|---|
| 여는 것 | 봉투. 받는 이, 보낸 이, 때, 본문의 지문과 종류를 읽는다 |
| 열지 않는 것 | 받는 이가 `lab:jdot-hq`가 아닌 편지의 본문과 서명 |
| 내주는 것 | 받는 이가 `lab:jdot-hq`인 편지만, 승인된 호출자에게 |
| 계정 | `lxm-mail-window`. 버킷의 권한이 `drop-root/hub-ops/` 아래의 목록과 읽기, `mail-audit/` 아래의 만들기로 막는다 |
| 권한이 막지 못하는 것 | 그 계정은 `hub-ops`의 **본문도 읽을 수 있다.** 읽지 않는 것은 코드이고, 막는 것은 권한이 아니다 |
| 기록 | 봉투를 가져온 호출마다 `gs://lxm-drop/mail-audit/<날짜>/…-read.json` 하나. 가져온 봉투·읽은 봉투·내준 편지의 문과 번호, 호출자, 때. 내용은 없다. 쓰지 못하면 내주지 않는다 |
| 승인의 기록 | 승인마다 `…-grant.json` 하나 |

**버킷에 쓰는 이가 둘이 된다.** 지금까지 버킷에 쓰는 것은 감독기뿐이었다. 창구의 계정이 `mail-audit/` 아래에
자기 기록을 만든다. 만들 수만 있고 고치거나 지우거나 읽지 못한다. 편지의 나무에는 쓰지 못한다(실측).

**이 문서에 적는 것.** 창구의 읽기는 건마다 여기에 옮기지 않는다. 버킷의 기록이 원본이다. 정기 기록(월 1회
이상)에 그 달의 `read` 기록 수와 가져온 봉투 수를 적는다. 창구의 계정으로 사람이 손으로 읽으면 위의 표에 센다.

**끄는 법.** 계정의 키를 지운다. 그 순간부터 창구는 편지에 닿지 못한다.

## 대리 서명 — Jdot HQ의 발신 (2026-10-12 개정)

위의 두 가지(손으로 연 것, 창구의 기계 열람)와 또 다른 것이 2026-10-12부터 생긴다. **운영자가 띄운 서비스가 한 연구소의
이름으로 서명한다.** 읽기가 아니라 쓰기이고, 드롭의 권한이 아니라 그 연구소의 키로 하는 일이라 따로 적는다.

**무엇인가.** `lab:jdot-hq`의 환경은 서명 키를 지닐 수 없다. JJ가 그 연구소 하나에 한해 예외를 정했다(Organum 196).
Jdot이 초안을 놓고(`mail_send/`의 초안 창구), JJ가 화면에서 받은 그대로의 글을 읽고 승인하면, 서명 서비스가 그 한 통에
k3으로 서명해 문 `hub-ops/from-jdot-hq`에 올린다. 코드는 organum 0.10.0의 `hub_draft`와 `hub_send`다.

| | |
